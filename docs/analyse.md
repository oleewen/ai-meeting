## 一、执行摘要

### 1.1 项目概述

本项目旨在开发一个会议室预约管理系统，为公司/组织提供统一的会议室预约管理平台。系统支持用户自助查询、预约、取消、签到以及查看个人预约记录，降低线下沟通成本，避免会议室使用冲突。

### 1.2 核心价值

- **提升效率**: 通过在线预约系统，减少线下沟通成本
- **避免冲突**: 实时查询可用会议室，防止预约冲突
- **自助服务**: 用户可自主完成预约、取消、签到等操作
- **数据统计**: 通过签到功能辅助统计会议室利用率

### 1.3 技术架构

- **架构模式**: DDD (领域驱动设计)
- **技术栈**: Spring Boot 2.7.10, Java 17, MyBatis
- **部署环境**: PC浏览器（Chrome、Edge、Firefox等）

## 二、业务背景与目标

### 2.1 业务背景

在传统的会议室管理方式中，存在以下问题：
- 会议室使用情况不透明，容易产生冲突
- 线下沟通成本高，效率低下
- 缺乏会议室使用数据统计，难以优化资源配置
- 无法提前规划会议室使用，影响会议安排

### 2.2 项目目标

1. **统一管理平台**: 提供集中的会议室预约管理平台
2. **降低沟通成本**: 减少线下沟通，提升预约效率
3. **避免使用冲突**: 实时查询可用会议室，防止预约冲突
4. **支持自助服务**: 用户可自主完成查询、预约、取消、签到等操作
5. **数据支持决策**: 通过签到功能辅助统计利用率，支持后续优化

### 2.3 目标用户

- **主要用户**: 公司/组织内部员工
- **次要用户**: 系统管理员（可选扩展）

## 三、用户角色与使用场景

### 3.1 用户角色

#### 3.1.1 普通员工用户

**角色描述**: 需要使用会议室进行会议的公司员工

**核心权限**:
- 查询会议室可用情况
- 预约会议室
- 取消自己创建的预约
- 签到会议
- 查看"我的预定"列表

**使用场景**:
1. **场景1 - 查询可用会议室**
   - 用户需要在下周三下午2-4点召开部门会议
   - 用户打开系统，选择日期和时间段
   - 系统显示符合条件的可用会议室列表
   - 用户查看会议室详情，选择合适会议室

2. **场景2 - 创建预约**
   - 用户选择了会议室和时间段
   - 填写会议主题、参会人数、备注信息
   - 系统验证时间冲突和业务规则
   - 预约成功，显示预约详情

3. **场景3 - 取消预约**
   - 用户发现会议需要取消
   - 在"我的预定"中找到对应预约
   - 点击取消，系统验证是否允许取消（时间规则）
   - 确认取消，系统释放会议室占用

4. **场景4 - 会议签到**
   - 会议即将开始（提前10分钟）
   - 用户在"我的预定"中找到对应预约
   - 点击签到按钮
   - 系统验证签到时间窗口，标记为"已签到"

5. **场景5 - 查看我的预定**
   - 用户想查看本周的所有预约
   - 打开"我的预定"页面
   - 按日期范围筛选，查看预约列表
   - 可以查看详情、取消、签到等操作

**核心权限**:

- 管理预约记录（强制取消、调整）

## 四、功能需求详细分析

### 4.1 功能1: 会议室查询

#### 4.1.1 功能目标

用户能够快速找到在指定时间段可用的会议室，支持多条件筛选和排序。

#### 4.1.2 输入条件

**必填条件**:
- 日期（Date）
- 开始时间（StartTime）
- 结束时间（EndTime）

**可选过滤条件**:
- 会议室地点/楼层（Location/Floor）
- 容量（Capacity）- 可容纳人数
- 设备（Equipment）- 投影/大屏、视频会议、白板等

#### 4.1.3 功能点

1. **查询逻辑**:
   - 根据日期和时间段查询可用会议室
   - 排除在该时间段已被预约的会议室
   - 支持按过滤条件进一步筛选

2. **列表展示**:
   - 会议室名称
   - 所在地点/楼层
   - 可容纳人数
   - 支持设备列表
   - 当前查询时间段内是否可用（可用/被占用）
   - 可用状态标识（绿色=可用，红色=被占用）

3. **排序与筛选**:
   - 支持按容量排序（升序/降序）
   - 支持按位置排序
   - 支持按可用状态筛选

4. **详情查看**:
   - 点击会议室可查看详情
   - 显示当日时间轴排期（可视化展示已预约时间段）
   - 显示会议室完整信息（设备、容量、位置等）

#### 4.1.4 业务规则

- 查询时间段必须有效（开始时间 < 结束时间）
- 查询日期不能是过去日期（可选规则）
- 被占用的会议室需要显示占用时间段信息

#### 4.1.5 输出结果

- 符合条件的会议室列表
- 每个会议室的详细信息
- 可用状态标识

### 4.2 功能2: 会议室预约

#### 4.2.1 功能目标

用户能够创建会议室预约，系统自动验证冲突和业务规则。

#### 4.2.2 输入信息

**必填信息**:
- 会议室（MeetingRoom）- 从查询结果中选择
- 日期（Date）
- 开始时间（StartTime）
- 结束时间（EndTime）
- 会议主题（Subject）

**选填信息**:
- 参会人数（AttendeeCount）- 推荐填写
- 备注信息（Remark）

#### 4.2.3 功能点

1. **预约创建流程**:
   - 用户从查询结果中选择会议室
   - 填写预约表单（主题、时间、人数、备注）
   - 系统验证业务规则
   - 创建预约记录
   - 返回预约成功提示

2. **冲突检测**:
   - 检查时间段是否与已有预约冲突
   - 冲突判断规则：时间段重叠即冲突
   - 冲突时提示具体冲突信息（哪个预约、时间段）

3. **业务规则验证**:
   - 开始时间 < 结束时间
   - 预约时间范围限制（如：只允许未来30天内预约）
   - 最短/最长会议时长（如：30分钟~4小时）
   - 提前预约截止时间（如：会议开始前5分钟不可新预约或修改）

#### 4.2.4 业务规则详细说明

**规则1 - 时间冲突检测**:
```
时间段A与时间段B冲突的条件：
- A的开始时间 < B的结束时间 且 A的结束时间 > B的开始时间
```

**规则2 - 预约时间范围限制**:
```
可预约日期范围：[今天, 今天+30天]
超出范围提示："只能预约未来30天内的会议室"
```

**规则3 - 会议时长限制**:
```
最短时长：30分钟
最长时长：4小时
不满足提示："会议时长必须在30分钟到4小时之间"
```

**规则4 - 提前预约截止时间**:
```
截止时间：会议开始前5分钟
规则：在截止时间之后，不允许新预约或修改该时间段的预约
```

**规则5 - 重复预约**:
```
第一期暂不支持，标记为后续迭代功能
```

#### 4.2.5 成功后处理

- 提示"预约成功"
- 显示预约详情（预约ID、会议室、时间、主题等）
- 将记录写入"我的预定"列表
- 可选：发送邮件/消息通知（第一期暂不实现）

#### 4.2.6 异常处理

- 冲突时提示："该时间段已被预约，请选择其他时间"
- 规则违反时提示具体违反的规则
- 网络异常时提示："网络异常，请稍后重试"

### 4.3 功能3: 预约取消

#### 4.3.1 功能目标

用户能够取消自己创建的预约，系统验证取消规则并释放会议室占用。

#### 4.3.2 前置条件

- 用户已登录
- 用户对该预约有取消权限（只能取消自己创建的预约）
- 系统可设置"离开始时间太近是否允许取消"规则

#### 4.3.3 功能点

1. **取消流程**:
   - 用户在"我的预定"中找到要取消的预约
   - 点击"取消"按钮
   - 系统弹出确认提示
   - 用户确认后执行取消操作
   - 系统更新预约状态，释放会议室占用

2. **确认提示信息**:
   - 会议主题
   - 预约时间（日期、时间段）
   - 会议室名称
   - 取消的影响说明（如：通知参会人等）

3. **取消规则验证**:
   - 检查是否允许取消（时间规则）
   - 规则：离开始时间太近不允许取消（如：开始前5分钟内）
   - 规则：已签到的会议不允许取消（可选）

#### 4.3.4 业务规则

**规则1 - 取消时间限制**:
```
允许取消时间：会议开始前5分钟之前
不允许取消时间：会议开始前5分钟内
提示："会议即将开始，不允许取消"
```

**规则2 - 权限验证**:
```
只能取消自己创建的预约
尝试取消他人预约时提示："无权限取消该预约"
```

**规则3 - 状态验证**:
```
已取消的预约不能再次取消
已结束的预约不能取消
```

#### 4.3.5 取消成功后处理

- 预约状态变更为"已取消"
- 从可用会议室占用中释放该时间段
- 在"我的预定"中标记为"已取消"
- 可选：发送通知给相关人员（第一期暂不实现）

---

### 4.4 功能4: 签到功能

#### 4.4.1 功能目标

确认会议是否按计划使用，辅助统计会议室利用率。

#### 4.4.2 前置条件

- 用户已登录
- 用户是该条预约的创建人或受授权签到人
- 签到时间在允许的时间窗口内

#### 4.4.3 功能点

1. **签到流程**:
   - 用户在"我的预定"或预约详情中找到对应预约
   - 查看"签到"按钮状态
   - 在允许的时间窗口内点击"签到"
   - 系统验证签到时间规则
   - 标记预约状态为"已签到"

2. **签到时间规则**:
   - 可签到时间窗口：会议开始前N分钟 至 会议开始后M分钟
   - 示例：提前10分钟 至 延后15分钟可操作
   - 未到签到时间：按钮置灰或不显示
   - 超过签到时间：按钮置灰，显示"已过签到时间"

3. **状态管理**:
   - 未签到：显示"待签到"
   - 已签到：显示"已签到"，按钮置灰
   - 可选扩展：未签到的会议可标记为"未使用"或自动释放

#### 4.4.4 业务规则

**规则1 - 签到时间窗口**:
```
可签到时间：[会议开始时间 - 10分钟, 会议开始时间 + 15分钟]
提前签到：会议开始前10分钟之前，按钮置灰
正常签到：会议开始前10分钟至开始后15分钟，可操作
超时签到：会议开始后15分钟之后，按钮置灰，显示"已过签到时间"
```

**规则2 - 权限验证**:
```
只能对属于自己的预约进行签到
尝试签到他人预约时提示："无权限对该预约进行签到"
```

**规则3 - 状态验证**:
```
已取消的预约不能签到
已结束的预约不能签到
已签到的预约不能重复签到
```

#### 4.4.5 可选扩展功能（后续迭代）

- **签退功能**: 支持签退/结束会议，用于精确记录实际使用时长
- **自动释放**: 未签到的会议可标记为"未使用"或自动释放（配合硬件或管理员处理）

### 4.5 功能5: 查看"我的预定"

#### 4.5.1 功能目标

用户查看和管理自己的所有会议室预约记录。

#### 4.5.2 功能点

1. **列表展示**:
   - 会议主题
   - 会议室名称
   - 日期 & 时间段（开始时间 - 结束时间）
   - 状态（待开始 / 已签到 / 已结束 / 已取消 / 未签到等）
   - 参会人数（如有）
   - 备注信息（如有）

2. **查询条件**:
   - 日期范围筛选（默认展示最近一周或一月）
   - 状态筛选（全部/待开始/已签到/已结束/已取消）
   - 会议室筛选（可选）

3. **排序**:
   - 默认按时间排序（最新的在前）
   - 支持按日期排序
   - 支持按状态排序

4. **操作功能**:
   - **查看详情**: 点击预约项查看完整信息
   - **取消预约**: 符合规则时显示取消按钮
   - **签到**: 符合时间规则时显示签到按钮
   - **复制预约**: 快速再约下一次（可选扩展）

#### 4.5.3 状态定义

- **待开始**: 预约已创建，但会议时间未到
- **已签到**: 用户已完成签到
- **已结束**: 会议时间已过
- **已取消**: 用户已取消预约
- **未签到**: 会议时间已过但未签到（可选状态）

#### 4.5.4 业务规则

- 只能查看自己创建的预约
- 按时间倒序展示（最新的在前）
- 默认展示最近一周的预约
- 支持分页加载（如果数据量大）

## 五、领域模型设计（DDD视角）

### 5.1 聚合根识别

#### 5.1.1 MeetingRoom（会议室聚合根）

**职责**: 管理会议室的基本信息和状态

**属性**:
- `id`: 会议室ID（唯一标识）
- `name`: 会议室名称
- `location`: 位置信息（值对象）
- `capacity`: 可容纳人数
- `equipmentList`: 设备列表（值对象集合）
- `status`: 状态（可用/不可用/维护中）
- `description`: 描述信息

**行为**:
- `isAvailable(timeSlot)`: 检查指定时间段是否可用
- `updateStatus(status)`: 更新会议室状态

#### 5.1.2 Reservation（预约聚合根）

**职责**: 管理预约的完整信息和生命周期

**属性**:
- `id`: 预约ID（唯一标识）
- `meetingRoomId`: 会议室ID
- `userId`: 用户ID（创建人）
- `subject`: 会议主题
- `timeSlot`: 时间段（值对象）
- `attendeeCount`: 参会人数
- `remark`: 备注信息
- `status`: 预约状态（值对象）
- `checkInTime`: 签到时间（可选）
- `createTime`: 创建时间
- `updateTime`: 更新时间

**行为**:
- `cancel()`: 取消预约
- `checkIn()`: 签到
- `isConflict(otherReservation)`: 检查是否与其他预约冲突
- `canCancel()`: 检查是否可以取消
- `canCheckIn()`: 检查是否可以签到

### 5.2 实体识别

#### 5.2.1 User（用户实体）

**职责**: 管理用户信息

**属性**:
- `id`: 用户ID
- `username`: 用户名
- `name`: 姓名
- `email`: 邮箱
- `department`: 部门
- `role`: 角色（普通用户/管理员）

### 5.3 值对象识别

#### 5.3.1 TimeSlot（时间段值对象）

**属性**:
- `date`: 日期
- `startTime`: 开始时间
- `endTime`: 结束时间

**行为**:
- `isOverlap(other)`: 检查是否与其他时间段重叠
- `getDuration()`: 获取时长（分钟）
- `isValid()`: 验证时间段是否有效

#### 5.3.2 Location（位置值对象）

**属性**:
- `building`: 楼栋
- `floor`: 楼层
- `roomNumber`: 房间号

#### 5.3.3 Equipment（设备值对象）

**属性**:
- `type`: 设备类型（投影仪/大屏/视频会议/白板等）
- `name`: 设备名称
- `description`: 设备描述

#### 5.3.4 ReservationStatus（预约状态值对象）

**枚举值**:
- `PENDING`: 待开始
- `CHECKED_IN`: 已签到
- `COMPLETED`: 已结束
- `CANCELLED`: 已取消
- `NO_CHECK_IN`: 未签到（可选）

### 5.4 领域服务识别

#### 5.4.1 ReservationConflictChecker（预约冲突检查服务）

**职责**: 检查预约时间段是否冲突

**方法**:
- `checkConflict(reservation, timeSlot)`: 检查指定时间段是否与已有预约冲突
- `findConflicts(meetingRoomId, timeSlot)`: 查找指定会议室和时间段的冲突预约

#### 5.4.2 ReservationRuleValidator（预约规则验证服务）

**职责**: 验证预约是否符合业务规则

**方法**:
- `validateTimeRange(date)`: 验证预约日期是否在允许范围内
- `validateDuration(timeSlot)`: 验证会议时长是否符合要求
- `validateAdvanceBooking(timeSlot)`: 验证提前预约时间是否符合要求

#### 5.4.3 CheckInTimeValidator（签到时间验证服务）

**职责**: 验证签到时间是否在允许窗口内

**方法**:
- `canCheckIn(reservation, currentTime)`: 检查当前时间是否允许签到

## 六、业务规则详细说明

### 6.1 时间冲突检测规则

**规则描述**: 两个预约的时间段不能重叠

**判断逻辑**:
```
时间段A [startA, endA] 与时间段B [startB, endB] 冲突的条件：
startA < endB AND endA > startB
```

**实现要点**:
- 需要检查同一会议室的所有有效预约（排除已取消的）
- 需要检查时间段是否完全重叠或部分重叠

### 6.2 预约时间范围限制

**规则描述**: 只能预约未来指定天数内的会议室

**配置参数**:
- `maxAdvanceDays`: 最大提前预约天数（如：30天）

**判断逻辑**:
```
可预约日期范围：[今天, 今天 + maxAdvanceDays]
超出范围提示："只能预约未来{maxAdvanceDays}天内的会议室"
```

### 6.3 会议时长限制

**规则描述**: 会议时长必须在指定范围内

**配置参数**:
- `minDuration`: 最短时长（分钟，如：30）
- `maxDuration`: 最长时长（分钟，如：240）

**判断逻辑**:
```
会议时长 = endTime - startTime
必须满足：minDuration <= 会议时长 <= maxDuration
不满足提示："会议时长必须在{minDuration}分钟到{maxDuration}分钟之间"
```

### 6.4 提前预约截止时间

**规则描述**: 在会议开始前指定时间内，不允许新预约或修改

**配置参数**:
- `advanceBookingCutoffMinutes`: 提前预约截止分钟数（如：5分钟）

**判断逻辑**:
```
当前时间 + advanceBookingCutoffMinutes >= 会议开始时间
则不允许新预约或修改该时间段的预约
```

### 6.5 取消时间限制

**规则描述**: 离会议开始时间太近时，不允许取消

**配置参数**:
- `cancelCutoffMinutes`: 取消截止分钟数（如：5分钟）

**判断逻辑**:
```
当前时间 + cancelCutoffMinutes >= 会议开始时间
则不允许取消
提示："会议即将开始，不允许取消"
```

### 6.6 签到时间窗口

**规则描述**: 只能在指定时间窗口内签到

**配置参数**:
- `checkInAdvanceMinutes`: 提前签到分钟数（如：10分钟）
- `checkInDelayMinutes`: 延后签到分钟数（如：15分钟）

**判断逻辑**:
```
可签到时间窗口：[会议开始时间 - checkInAdvanceMinutes, 会议开始时间 + checkInDelayMinutes]
提前签到：当前时间 < 会议开始时间 - checkInAdvanceMinutes，按钮置灰
正常签到：在时间窗口内，可操作
超时签到：当前时间 > 会议开始时间 + checkInDelayMinutes，按钮置灰
```

## 十、风险评估与建议

### 10.1 技术风险

**风险1: 时间冲突检测性能**
- **描述**: 当预约记录量大时，冲突检测可能影响性能
- **影响**: 中等
- **缓解措施**: 
  - 使用数据库索引优化查询
  - 考虑使用缓存（如Redis）缓存热门时间段
  - 使用数据库查询优化冲突检测逻辑

**风险2: 并发预约冲突**
- **描述**: 多人同时预约同一时间段可能产生冲突
- **影响**: 高
- **缓解措施**:
  - 使用数据库乐观锁或悲观锁
  - 使用分布式锁（如Redis）保证并发安全
  - 在应用层进行二次验证

### 10.2 业务风险

**风险1: 业务规则变更**
- **描述**: 业务规则可能频繁变更（如时间限制、容量限制等）
- **影响**: 中等
- **缓解措施**:
  - 将业务规则配置化，避免硬编码
  - 使用策略模式处理不同的业务规则
  - 预留扩展接口

**风险2: 用户体验不佳**
- **描述**: 界面复杂、操作繁琐可能影响用户体验
- **影响**: 中等
- **缓解措施**:
  - 采用现代化UI框架，保证界面美观
  - 简化操作流程，减少用户操作步骤
  - 进行用户测试，收集反馈

### 10.3 项目风险

**风险1: 开发周期延长**
- **描述**: 需求变更或技术难点可能导致开发周期延长
- **影响**: 中等
- **缓解措施**:
  - 采用敏捷开发，分阶段交付
  - 优先实现MVP，快速验证
  - 预留缓冲时间

**风险2: 数据迁移**
- **描述**: 如果已有会议室数据，需要数据迁移
- **影响**: 低
- **缓解措施**:
  - 提前准备数据迁移脚本
  - 进行数据验证
  - 保留备份

### 10.4 建议

1. **采用配置化设计**: 将业务规则配置化，便于后续调整
2. **重视测试**: 特别是时间冲突检测和并发场景的测试
3. **文档完善**: 及时更新技术文档和API文档
4. **代码规范**: 遵循DDD架构规范，保证代码质量
5. **性能监控**: 上线后监控系统性能，及时优化
