## 新增需求
### 需求：查看我的预定
系统必须提供"我的预定"功能，允许用户查看和管理自己的所有会议室预约记录。

#### 场景：查看我的预定列表
- **当** 用户已登录
- **当** 用户访问"我的预定"页面
- **那么** 系统返回该用户的所有预约记录列表（按时间排序）
- **那么** 每条记录包含：会议主题、会议室名称、日期和时间段、状态（待开始/已签到/已结束/已取消/未签到）

#### 场景：按日期范围筛选预约记录
- **当** 用户提供日期范围筛选条件（默认显示最近一周或一月）
- **那么** 系统返回该日期范围内的预约记录列表

#### 场景：按状态筛选预约记录
- **当** 用户选择状态筛选条件（全部/未开始/已结束/已取消）
- **那么** 系统返回符合该状态的预约记录列表

#### 场景：查看预约详情
- **当** 用户点击某个预约记录
- **那么** 系统返回该预约的详细信息，包括所有字段和可执行的操作（取消、签到等）

## 新增需求
### 需求：取消预约
系统必须提供取消预约功能，允许用户取消自己创建的预约。系统必须遵守取消时间限制规则。

#### 场景：成功取消预约
- **当** 用户已登录
- **当** 用户是自己创建的预约的创建人
- **当** 取消时间符合规则（如距离开始时间超过5分钟）
- **当** 用户确认取消操作
- **那么** 系统将预约状态变更为"已取消"
- **那么** 系统释放该时间段，使会议室重新可用
- **那么** 系统返回取消成功响应
- **那么** 该预约从可用会议室占用中移除

#### 场景：取消预约失败（时间限制）
- **当** 用户尝试取消即将开始的预约（如距离开始时间不足5分钟）
- **那么** 系统返回取消失败响应，提示"会议开始前X分钟不可取消预约"
- **那么** 系统不修改预约状态

#### 场景：取消预约失败（无权限）
- **当** 用户尝试取消不是自己创建的预约
- **那么** 系统返回权限错误响应，提示"只能取消自己创建的预约"
- **那么** 系统不修改预约状态

#### 场景：取消预约确认提示
- **当** 用户点击取消按钮
- **那么** 系统弹出确认提示，显示：会议主题、时间、会议室、取消的影响说明
- **当** 用户确认取消
- **那么** 系统执行取消操作

## 新增需求
### 需求：会议签到
系统必须提供会议签到功能，允许用户在会议开始前后的时间窗口内进行签到，以确认会议按计划使用。

#### 场景：成功签到
- **当** 用户已登录
- **当** 用户是该预约的创建人或受授权签到人
- **当** 当前时间在签到时间窗口内（会议开始前N分钟到开始后M分钟，如提前10分钟至延后15分钟）
- **当** 用户点击签到按钮
- **那么** 系统将预约状态标记为"已签到"
- **那么** 系统返回签到成功响应
- **那么** 预约记录显示"已签到"状态

#### 场景：签到失败（未到签到时间）
- **当** 用户尝试在签到时间窗口之前进行签到
- **那么** 系统返回签到失败响应，提示"签到时间未到，请在会议开始前X分钟至开始后Y分钟内签到"
- **那么** 系统不修改预约状态
- **那么** 签到按钮置灰或不显示

#### 场景：签到失败（超过签到时间窗口）
- **当** 用户尝试在签到时间窗口之后进行签到（如会议开始后超过15分钟）
- **那么** 系统返回签到失败响应，提示"签到时间已过"
- **那么** 系统不修改预约状态

#### 场景：签到失败（无权限）
- **当** 用户尝试对不是自己创建的预约进行签到
- **当** 且用户不是受授权签到人
- **那么** 系统返回权限错误响应，提示"只能对自己的预约进行签到"
- **那么** 系统不修改预约状态

#### 场景：已签到状态显示
- **当** 用户已成功签到
- **当** 用户查看该预约记录
- **那么** 系统显示"已签到"状态
- **那么** 签到按钮不再显示或显示为"已签到"
